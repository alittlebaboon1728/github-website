# 栏目与分类切换提速

更新日期：2026-11-02。目标是让已浏览或已预加载的内容立即显示，并保持切换期间可操作。

## 语言与排序筛选提速（2026-11-02）

原来只预热默认语言/星标排序的六个分类，切换语言或排序会进入全新范围，先等待 GitHub，再排队补齐中文。现在 `shared/discovery-filter.mjs` 同时供前后端使用：服务端从全部保存页面恢复中文项目索引，浏览器复用原有 `/api/observatory/catalog` 数据，无需再下载一份索引。用途标签、主语言严格匹配，按星标或推送时间排序，稳定分页；只采用公开、名称对应且有中文概括的真实项目。

- 未有准确页面时，已有中文立即显示，标记“已收录范围匹配”，后台补全更多结果；本机无匹配时明确提示仍在查找，不误报整个 GitHub 无结果。临时相关性排序使用本机星标顺序，等待上游准确结果。
- 当前条件独立于常驻顺序准备通道，使用前台优先级；同范围/页合并，新选择优先于尚未开始的旧选择。已执行的任务不能抢占，GitHub 冷却继续遵守。
- 完整结果替换临时匹配时，从第一页重新分页，清除同范围的旧临时资源，避免两套结果混页。后续页尚未完整时保留已经显示的页面。
- 轮询临时范围每 1.5 秒一次，普通中文准备每 2.5 秒一次；离开范围停止该视图轮询。请求或准备失败保留已匹配中文、停止无效轮询，可手动重试。
- 本机匹配仅适用于界面的标准用途/语言筛选；任意关键词和高级 GitHub 条件不使用本地猜测。首次未收录项目及完整上游排序仍需后台完成，不能承诺所有条件的完整结果瞬间就绪。

验证：106 项服务端通过；全套浏览器原检查 78/79，新增分页检查暴露并修复旧临时分页缓存问题后，相关 12/12 通过；正式构建通过。覆盖 C++ 与 C 区分、精确标签、中文来源、重启恢复、前台补全去重、网络挂起时下一帧显示、失败保留及临时/准确分页转换。

正式服务 PID 15276。`node scripts/verify-discovery-filters.mjs` 使用实际目录和实际筛选 API，在 1440/1280/390px × 深浅主题依次切换七种语言、最近更新与相关性排序，共 54 次；人为给筛选响应增加 1000ms 后，下一帧仍显示正确语言的中文卡，无加载骨架、页面错误、横向溢出或浏览器 POST。切换耗时 14.3–121.7ms，中位数 38.3ms、P95 83.4ms。54 次真实 API 全部 200，全部为本机匹配预览，未计人为延迟的接口耗时 5.20–134.92ms，中位数 8.24ms、P95 48.10ms。报告和六张截图在 `.build/filter-speed/`；`FILTER_BASE_URL` 可指定网站，`FILTER_API_DELAY_MS` 可修改额外延迟。

这些是本机 Edge 的视口样本；耗时从变更事件计到下一动画帧，验证缓存显示不等待接口，不代表真实 iPad Safari、跨设备网络或完整上游查询耗时。

## 原有栏目与分类缓存

后续已按用户要求加入 [常驻中文项目库](PERSISTENT_CHINESE_LIBRARY.md)：生产服务器无人访问时也生成并长期保存中文卡，页面直接读取，启动时预热六个分类和默认榜单前三页。下文“进入页面才生成、完整刷新重新读取”的边界是此前版本；当前浏览器一次预取六个分类前三页，数据源为持久中文库。原有测速关闭了中文生成，当前另有中文开启模式的独立生产验收。

## 实现

- `src/resourceCache.ts` 提供共享 GET 缓存：首次渲染同步读取缓存，同一资源的请求合并；离开页面只解除订阅，不取消其他页面或预加载正在使用的请求。搜索/榜单保鲜 5 分钟，README 10 分钟，试用目录/状态 15 秒；过期内容继续显示，同时后台更新。手动刷新绕过保鲜期。网络错误保留已读内容。
- 缓存最多保留 80 个资源；查询列表另保留最多 24 个范围。缓存仅在当前浏览器页面内存中，不保存 AI 对话；完整刷新页面会重新读取，仍可利用服务端已有持久缓存。
- `src/useDiscoverySearch.ts` 按查询和排序独立保存仓库列表、页码、分页终点、来源与错误。分类、语言、排序共同形成查询键，切回之前的范围直接恢复全部已加载分页。迟到的响应只更新自己的范围，分页失败仍重试失败页。
- 卡片瀑布流批量读取高度、再统一写入行跨度；尺寸观察直接使用浏览器提供的边框高度，减少每张卡读写交错造成的同步排版。
- 去除刷新期间整张列表的 `inert` 和半透明禁用状态，缓存结果可继续收藏、查看。首次未命中的请求保留加载反馈；接口失败不会把其他分类或离线快照冒充成当前结果。
- 可见内容就绪后，通过空闲回调逐个预加载默认榜单及六个分类的第一页；同时只运行一个空闲任务。导航/分类的悬停、键盘聚焦与触摸提前读取目标。后台标签、离线、节省流量及 2G 连接跳过预加载，预加载失败短暂退避。
- 四个主栏目、生成试用阅读页和项目阅读页随主界面载入，消除首次进入时额外等待页面脚本。Excalidraw 编辑器仍由明确点击才加载。
- 首页和试用列表共读同一份目录，试用卡的交互意图提前读取已保存详情。生成后使目录失效并写入最新项目状态；并发中的旧 GET 不得覆盖生成结果，失效资源会重新读取。生成任务仍按实际状态轮询。
- README、配图元数据和首页 GitHub 动态复用已读内容，避免重新挂载的空状态。修复轮播在页面移除或零宽布局下收到滚动事件时的除零和索引错误。

浏览器预加载只发 GET，不提交中文生成、AI 推荐或试用 POST；服务端中文库持续准备默认和已访问范围。AI 推荐及试用仍由用户明确提交。标准语言/用途筛选可先显示匹配的已有中文，未收录项目和完整上游结果由后台补齐；高级查询未命中时仍需真实服务。

最终正式内网实测：四组尺寸/主题的 28 次缓存切换为 8.3–58 毫秒，中位数 22.05 毫秒；每次均在下一次动画帧显示目标内容，无加载占位、禁用、额外 GET、页面异常或横向溢出。API 已额外加入 800 毫秒延迟，未实际调用模型。该样本说明缓存切换不再等待该 API 延迟，不作为所有设备的固定耗时承诺。当前正式服务 PID 52048，入口 `http://10.198.101.205:4173`。

生产验证截图、精确耗时和请求记录保存在 `.build/navigation-speed/`。这是同一台电脑经 WLAN 地址访问的浏览器样本，不代表另一台物理设备或所有网络；耗时从点击计到下一次动画帧，覆盖路由事件与界面提交，适用于已预加载或已浏览的目标。
