# 搜索与中文概括提速

日期：2026-11-01。保留项目隔离、公开性验证、真实来源和原文证据核对。没有更换模型或降低硬条件核验标准。

## 改动

- 普通搜索先给仓库列表。前三页的读取不再等待前一页中文生成；“加载更多”可在已有概括仍生成时使用，新旧任务同时更新。
- 七天中文缓存先查后排队，其他项目生成不会挡住已有内容。README 读取并发 3，与模型生成分开调度；生产环境中文生成默认并发 4。提示词只发送带编号的原文片段，移除重复的整份 README，限制输出预算为 2,200 tokens。
- 需求解析通常要求两条短查询，最多三条。每条查询有结果就按份额开始读取与核验，为其他查询保留候选名额；最后按查询轮转顺序补齐，最多 10 个项目，每份 README 只读一次。
- AI 核对默认并发 4，空出一个位置就处理下一个项目。每次模型只接收当前项目资料；通过原文和硬条件校验后，立即通过 NDJSON `partial` 事件返回，最多展示 8 项。
- 中文生成与搜索共用模型并发上限 6，交互请求优先于排队中的后台概括。可用 `AI_CONCURRENCY`、`AI_CARD_CONCURRENCY`、`AI_SEARCH_CONCURRENCY` 调整（范围 1–8）；降低上限可适配额度较小的服务。
- 重复 AI 请求共享计算和进度。最后一个观看者停止或离开后，中止模型请求并取消未开始的工作；其他观看者仍在时继续。成功结果缓存 10 分钟，缓存命中不占活动任务名额。已验证的部分结果在取消或连接失败后保留，并明确未完成。
- 修复 HTTP 局域网下 AI 入口崩溃：对话入口 ID 改用 `crypto.getRandomValues`，避免调用只在安全上下文可用的 `crypto.randomUUID`；每次新入口仍有独立随机 ID。
- 已有 `is:public` 不再重复附加，避免相同搜索产生不同缓存键。REST 仍遵守原来的 6.1 秒匿名 / 2.1 秒带令牌搜索间隔；新查询需要等待时可同时尝试公开网页，最快的有效结果返回，网页失败不拖住 REST。这会在快速切换查询时增加一次备用来源读取，所有来源继续独立限流和冷却。
- raw README 允许最多 4 个请求并行，core 最多 2 个，保留请求间隔。raw 连接超时 4 秒，失败后短暂冷却 15 秒，避免同一不可达主机对每份文件重复超时；REST 搜索保留 12 秒上限，网页/core 为 10 秒。卡片首次状态检查从 500 降到 100 毫秒，持续轮询从 1,200 降到 600 毫秒。

## 相同模拟延迟下的比较

`scripts/benchmark-search.mjs` 不联网、不调用模型。README 固定延迟 30 毫秒、模型 60 毫秒，其中一项 AI 核对故意延迟 240 毫秒。旧版默认并发 2，新生产配置并发 4；以下包含并发和调度两方面的变化，不能当作公网响应承诺。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 三页共 36 个仓库可浏览 | 1,155 ms | 5 ms |
| 第一张中文卡 | 127 ms | 124 ms |
| 36 张中文卡全部完成 | 1,715 ms | 652 ms |
| 首批可用 AI 推荐 | 639 ms | 108 ms |
| AI 核对全部完成 | 639 ms | 296 ms |

第一张概括仍需要读取来源并调用模型；本次主要消除批量等待、缓存排队和慢任务拖累。

复验新生产配置（PowerShell）：

```powershell

$env:BENCH_AI_CONCURRENCY='4'

```

## 真实接口检查

使用实际 GitHub 与官方 DeepSeek `deepseek-flash`，独立内存缓存，无持久化写入；没有改动 `.data/`、`.data-lan/` 的已有项目内容。最终一轮结果：

| 请求 | 耗时与结果 |
| --- | --- |
| 普通搜索 `repo:markedjs/marked is:public` | 首次 1,051 ms，返回真实仓库；同查询缓存小于 1 ms（进程内计时） |
| Marked 中文卡 | 4,345 ms，其中模型 3,516 ms；含中文概括与原文绑定的能力说明 |
| “推荐能把 Markdown 转成 HTML 的 JavaScript 开源库” | 首批 5,811 ms，全部 18,390 ms；核对 10 项，返回 5 个有依据的推荐 |
| 同一句 AI 搜索 | 4 ms，通过 HTTP 返回缓存，不再调用模型 |

真实结果包含 Showdown、markdown-js、simple-markdown、markdown-it 和 render-markdown-javascript。此次模型仍生成了三条查询；查询条数由需求解析决定。速度取决于网络、来源可用性和模型负载。排查期间出现过公开网页超时及检索失败，已修正备用来源阻塞与重复搜索条件；未将失败轮次计作成功测速。

最终原始记录：`.build/search-speed-live.json`；早期排查记录保留在同目录。执行 `node --env-file-if-exists=.env.local scripts/verify-search-speed-live.mjs` 会真正生成一张卡和进行一次 AI 检索（最多 12 次模型调用，卡片纠错可能另加一次），并复验缓存。
