# 常驻中文项目库

日期：2026-11-02。此实现替代此前仅靠浏览器缓存、进入分类才提交中文任务的流程。

最新补充：语言/排序切换现在从共享中文索引立即显示已有匹配，再后台补全准确范围。已部署 PID 15276；54 次真实缓存切换中位数 38.3ms、P95 83.4ms，筛选接口额外延迟 1 秒也不阻塞下一帧。完整记录见 [导航与筛选性能](NAVIGATION_PERFORMANCE.md)。

## 行为

- 正式服务启动后，即使没有访客，也会按顺序准备六个发现分类及默认累计星标榜的前三页；先覆盖各分类第一页，再补第二、三页。每页 12 项，榜单展示前 30 项。
- 搜索列表直接附带已保存的中文概括。浏览器一次读取 `/api/observatory/catalog`，预取六个分类前三页；切换和前两次“加载更多”直接复用这些数据。榜单也直接返回中文，无需浏览器重新提交生成任务。
- 后续访问的关键词、语言、排序和榜单筛选也会登记到服务端，至少准备前三页；更深页按访问范围补齐。标准用途/主语言筛选未有完整页面时，先从已收录中文索引严格匹配，注明仅覆盖已收录范围；浏览器复用原分类目录，不新增索引下载。当前条件用独立前台通道补全，临时结果每 1.5 秒读取进度，普通中文准备每 2.5 秒；完整结果替换时重置分页并失效临时页缓存，失败保留匹配内容、停止无效轮询并可重试。任意关键词和高级 GitHub 语法保留原查询流程，不把本地近似匹配当作准确结果。
- 列表默认每 30 分钟检查更新，缺失/失败内容默认两分钟后重试，并遵守 GitHub 返回的冷却时间。中文正文复用原有七天保鲜期，简介/主题或模型变化会重新核对。保鲜期到期只触发更新，旧中文继续可读；新列表未全部准备好时保留上一份完整列表。
- 中文生成与现有逐项目来源核验、任务去重和并发队列共用；后台优先级低于用户主动搜索，不占四个前台卡片任务名额。模型收到的资料仍按项目隔离。
- AI 需求搜索和项目试用仍由用户明确提交；常驻生成只处理公开项目的中文卡，不自动生成试用。

## 持久化与运行

生产目录为 `.data-lan/`，开发目录为 `.data/`；一个目录只能由一个 Node 进程写入。

| 文件 | 用途 |
| --- | --- |
| `card-<仓库摘要>.json` | 逐项目中文概括及来源 |
| `discovery-page-<范围摘要>-<页码>.json` | 已准备页面、原始公开列表与中文卡 |
| `discovery-library.json` | 分类/访问范围、更新及重试进度 |

页面和中文卡长期保存在服务器磁盘，不受共享 GitHub 响应缓存的条数/容量淘汰影响；内存淘汰不删除文件。服务重启后读取全部登记范围的保存页面，重建共享中文索引，索引内存最多 3000 个项目，磁盘仍长期保留。文件原子替换，保存失败不破坏上一份完整文件。恢复/迁移时保留整个数据目录。

`npm start` / `npm run lan:start` 默认开启常驻准备，需要模型已配置且磁盘持久化开启。`DISCOVERY_BACKGROUND=off` 可关闭。Vite 开发/预览默认关闭，显式设置 `DISCOVERY_BACKGROUND=on` 才开启；构建不会启动后台任务。`DISCOVERY_REFRESH_MINUTES` 默认 30，最小 1。

`GET /api/observatory/status` 的 `discoveryBackground` 表示当前是否可用；`GET /api/observatory/library/status` 返回各范围已准备数量、缺失数量、更新时间及重试状态。
