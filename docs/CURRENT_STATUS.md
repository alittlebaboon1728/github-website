## AI 与数据

- 项目试用使用独立 `TRIAL_AI_BASE_URL` / `TRIAL_AI_MODEL` / `TRIAL_AI_API_KEY`。本机按用户提供的地址接入 `https://api.yorozumoon.cn/v1`，模型精确为 `gpt-6.1-sol`。密钥在服务器读取 `api.txt` 的 gpt 标签（或环境变量）；中文卡与问答继续使用 DeepSeek。不得输出密钥。
- 试用只在明确提交后生成。GET、页面刷新、读取列表都不调用模型；同项目任务合并，同时最多两个生成任务，失败可重试，重新生成失败时保留旧体验。成功结果保存在 `.data/project-trials.json`，保留最近 64 个项目；无持久化时明确显示重启限制。

- 用户确认采用官方 DeepSeek `deepseek-flash`。配置只由服务端读取；不读取或输出密钥文件内容，不把凭据写入前端或记录。
- 中文项目卡首次准备 3 页 × 12 项，加载更多只新增下一页；逐张进度、失败重试及持久缓存保持。此前真实验收共生成 48 张卡。
- 榜单通过 `POST /api/observatory/cards/ranking` 提交筛选条件和仓库名，由服务端核对当前榜单范围后生成。与发现页共享七天总结缓存；首批 10 项，按需展开后只为缺失内容调用模型。真实榜单前 10 项验证使用已有生成缓存，不代表本轮新生成 10 张卡。
- 项目问答复用 `POST /api/observatory/recommend`，带可选 `repo`，依据该项目 README 回答；原文引用折叠显示，不同项目缓存隔离。
- DeepSeek 与 GPT 的每次请求均重新构造 `system` 和当前输入，不使用共享聊天历史或会话 ID。项目问答最多携带当前会话的 8 条用户提问；离开、刷新或从新入口进入不继承旧对话。卡片和试用纠错最多一次，且只使用当前项目的生成结果。
- 需求推荐先解析需求，再由 GitHub 统一调度取得最多 10 个不同候选的 README，最后分别提交 DeepSeek；每次仅包含一个候选，程序按原文证据核验后汇总最多 8 项。单项失败不重新读取 GitHub；全部模型核对失败时返回错误，保留模型 429 状态。
- GitHub REST 限流或网络失败时，可回退匿名公开 README，或验证公开标记及仓库名称后提取 GitHub 正文。404/已知私有仓库不绕过校验；资料不足明确无法确认。
- 已真实验证 Excalidraw 项目问答：经公开正文回退，DeepSeek 返回中文用途说明及 3 段原文引用。
- GitHub 搜索每个查询最多覆盖前 1,000 项，不能承诺 GitHub 全量收录；一般多轮推荐的真实质量仍需独立验收。历史增长需实际跨日快照，不补造数据。
