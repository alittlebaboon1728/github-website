# GitHub 请求限流处理

日期：2026-11-01。延续现有 UI，本轮只调整数据获取及来源/缺失字段的显示。

## 原因与实测来源

当前服务没有配置 GitHub Token。匿名 REST 普通请求为每小时 60 次、搜索为每分钟 10 次；两类额度独立。此前普通代理只缓存 5 分钟且不持久化，首页前三页、榜单、README 与推荐共同消耗额度，限流后大多数入口直接报错。

本次实际访问的来源：

| 来源 | 实测结果 | 本轮使用方式 |
| --- | --- | --- |
| GitHub REST `/rate_limit` | 200，返回 core 60 / search 10 的限制 | 保留官方接口，降低请求量并按返回时间冷却 |
| GitHub 公开仓库搜索页 | 200，包含仓库、真实 stars、语言、主题与分页数据 | REST 限流/连接失败时使用；保持关键词、排序与筛选 |
| GitHub 公开仓库页 | 200，包含公开标记、精确仓库身份、stars/forks、README | 详情、README 和项目图片共享页面缓存 |
| ecosyste.ms 仓库 API | 200；Excalidraw 示例最后同步时间为 2026-10-28 | 未接入为实时替代，避免把旧索引或不同搜索语义当作 GitHub 当前结果 |
| OSSInsight repository overview | 实测 500，响应提示其上游 401 | 未用于搜索或详情；原先成功使用的动态组件接口保留 |

参考：[GitHub 官方限额说明](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)、[公开仓库搜索](https://github.com/search?q=whiteboard&type=repositories)、[ecosyste.ms API 文档](https://repos.ecosyste.ms/docs/index.html)。

## 当前行为

1. 所有入口共用 `createGitHubClient`：普通搜索代理、AI 中文卡片、需求推荐、项目详情、README、榜单与活动。Vite 开发/预览及生产服务使用相同接入方式。
2. 三个连续的 12 项页面共用一次 36 项 REST 搜索请求。后续 UI 仍按 12 项分页，AI 仍只生成用户请求的页。榜单独立保持 30 项。
3. 无 Token 的不同 REST 搜索请求至少间隔 6.1 秒；有 Token 时 2.1 秒。公开网页至少间隔 1 秒，每类队列有长度上限。读取超时从真正发出请求时起算。
4. REST 搜索、REST 普通请求、网页与 raw 文件分别记录冷却状态。遇到 403/429 或额度归零，依据 `Retry-After` / `x-ratelimit-reset` 停止继续请求该来源，冷却状态持久化。
5. 搜索失败时读取匿名公开搜索页，将网页每页 10 项准确转换为站内每页 12 项，保留 1,000 项边界。验证返回页码、公开性及关键字段；登录页、挑战页、格式变化与不完整分页不会伪装成有效空结果。
6. 搜索结果复用为仓库元数据，减少逐项目 REST 请求。仓库详情失败时核对公开网页的身份与公开标记。
7. README 优先读取 raw 文件，再读取公开仓库页中的 README，最后才使用 REST。卡片生成和阅读共用文档缓存；项目图片复用已读取的公开页面。所有页面仅解析数据，不执行脚本。
8. 搜索缓存 10 分钟，元数据 1 小时，README 6 小时。成功响应持久化，重启后复用；上游不可用时可展示最多 7 天内的同一查询缓存，保留原始采集时间并标注过期。不同查询之间不替换结果，404/无效搜索不走过期缓存。
9. 持久缓存最多 120 条、约 6 MB，内存结果最多 160 条，HTML 最多 32 页；沿用单进程拥有 `.data/` 的部署约定。`OBSERVATORY_PERSISTENCE=off` 可关闭落盘。
10. 网页搜索缺少的 forks、推送时间、创建时间、议题数以 `null` 表示。前端省略缺失的派生数，时间显示“更新时间未提供”，详情显示“未提供”；不使用 0 或抓取时间冒充。来源说明放在现有信息浮层及 README 说明中。

## 验证

- `npm run build` 通过。
- 45 项后端测试通过，包含新增的 12 项解析、批量请求、分页、缓存重启、原始时间保留、私有/404、限流冷却、请求节奏和 HTTP 接入检查。
- 41 项浏览器测试通过。新增用例验证公开网页字段缺失时仍可浏览、收藏及打开快速了解，并且手机页面无溢出；原有搜索、推荐、对话、图片、主题和真实白板编辑器测试保持通过。
- `node scripts/verify-github-resilience.mjs` 实际联网检查：正常读取 3 页共 36 个项目只请求 1 次 REST；模拟 REST 429，真实公开网页返回 12 个搜索结果及 Excalidraw 仓库资料/README。此验证不调用模型，也不通过耗尽额度制造限流。
- 当前 `http://localhost:5173/api/github/search` 已返回新客户端的 `provider: github-api` 与真实 12 项结果，确认开发服务已经使用新实现。

联网检查原始记录在 `.build/github-resilience-live.json`；可运行上述脚本重新验证。原服务文件备份在 `.build/github-resilience-backup/`。

## 边界

公开网页也可能限流或改版，因此这套实现降低额度消耗并在有可信来源时继续工作，不能保证无限请求。所有来源不可用且没有对应缓存时仍显示错误。可继续在服务端配置自己的 `GITHUB_TOKEN` 提高官方额度，不需要为本轮降级功能新增密钥。未接入公共代理、未知镜像或第三方凭据。
