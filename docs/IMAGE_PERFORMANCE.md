## 实现

- `server/image-cache.mjs` 负责服务端下载与 Sharp 转码。封面生成最长宽度 480 / 960px 的 WebP，头像按 80px 生成；GIF 卡片使用首帧。图片按内容哈希存放在 `images/<sha256>.webp`，URL 为 `/api/observatory/images/<sha256>.webp`。
- JSON 来源索引与图片文件都持久化在当前数据目录。正式服务为 `.data-lan/`，开发服务为 `.data/`；内存淘汰不会删除磁盘文件。迁移时保留整个目录。每个目录仍只允许一个写入进程。
- 图片接口只读取已经生成的文件，提供一年 immutable 缓存、ETag、条件 GET、HEAD 和正确的 Content-Length。读取请求不会现场下载外网图片。内存图片副本最多约 32 MiB。
- `server/repository-media.mjs` 将缓存地址附加到列表项目。服务启动时从已有分类与榜单页面安排准备，每分钟检查已登记项目。图片下载并发 4；网络失败至少冷却 5 分钟；七天后的旧图先返回、后台更新，更新失败保留旧图。明确不可用的图片保存一天的否定记录，避免反复下载同一无效来源。
- README 元数据最多并发读取 3 项，沿用共享 GitHub 客户端，并以低优先级排队。中文概括、普通列表和 AI 搜索无需等待缩略图下载。
- 旧图片元数据会重新经过筛选：过滤被 camo 包裹的 SVG、徽章和贡献者拼图；GitHub 附件的短期签名地址转成公开附件地址，避免长期保存五分钟后失效的链接。头像使用 GitHub 官方编号 CDN；本机验证它可以避开主头像域名的连接超时。
- 浏览器根据 `srcSet` / `sizes` 选择尺寸，提供宽高、异步解码及屏幕外懒加载。分类目录和悬停意图预取前几项本机缩略图，最多并发 3 个，省流量及慢速连接跳过。加载失败按具体地址记录，更换成新缓存图后能恢复显示；小尺寸缩略图使用服务端已验证的封面尺寸，避免压缩后高度不足 100px 被误删。
- 本机后台“服务与存储”显示图片数量及占用空间。

下载仅接受已验证公开项目资料中的指定 GitHub 图片域名；每次重定向继续验证来源，不向图片源发送模型或 GitHub 凭据。单图上限 10 MiB、4000 万像素、12 秒超时，只输出解码后的 WebP。公共图片接口只接受固定格式的内容哈希，不提供任意 URL 代理。

首次出现的来源、失效原图及新更新的封面仍需要后台下载；已缓存的图片可直接复用。README 全文中任意第三方内嵌图仍按文档链接读取，本轮缓存针对卡片与快速阅读封面及头像。
